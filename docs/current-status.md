## 5. 既知の問題

### Supabaseへ運動報告が保存されない
**確認済み**

ブラウザ上では運動報告が成功し、localStorageの履歴・ポイント・連続記録が更新されたにもかかわらず、Supabase側に新しいレコードが確認できないケースがあります。

**コードからの推定**

アプリが現在送信しているキーは主に次のとおりです。

- `date`
- `exercise`
- `time`
- `mood`
- `comment`

これまで確認したSupabaseテーブルでは `exercise_date`, `exercise_time`, `user_name` など異なる列名が存在していました。送信データとテーブル定義の不一致が原因候補です。

ただし、RLSポリシーや必須列など別の原因もあり得るため、レスポンスと実際のスキーマを確認するまでは原因を確定しません。

### Supabase失敗時にもローカル処理が進む
**確認済み**

`saveReportToSupabase(reportData)` の完了を待たずに、localStorage保存、ポイント付与、連続記録更新、当日の報告済み処理が進みます。

そのため、利用者からは成功したように見えても、Supabase保存だけ失敗している状態が起こり得ます。

### データが端末・環境ごとに分かれる
**確認済み / コードからの推定**

主要データをlocalStorageに保存しているため、異なるブラウザやオリジンでは同じデータを共有できません。複数ユーザー・複数端末での利用には中央保存とユーザー識別が必要です。

**ユーザーヒアリングに基づく確認事項**
